# Phase 1 — Platform foundation

Everything else depends on this phase. Three tasks are complete and verified;
five remain.

---

## TASK-101 — Monorepo, tooling, CI ✅

**Delivered.** pnpm workspaces + Turborepo; `apps/{site,dashboard,api,edge}`;
nine `packages/*`; shared `tsconfig.base.json`; Prettier; CI running format,
typecheck, build, test, migrations and a schema-drift check.

**Two constraints this established**, both found by running the code rather
than reading about it:

- Relative imports use `.ts` extensions. Node's type-stripping does not remap
  `.js` → `.ts`, and workspace packages ship source.
- **Constructor parameter properties are banned.** Strip-only mode rejects
  them, because they emit runtime code.

## TASK-102 — Database schema, migrations, RLS ✅

**Delivered.** 58 tables, 19 enums, generated migration, RLS policies, the
`bos_app` role, and an isolation test that runs against a real Postgres.

**What the test caught.** The first isolation test passed while returning every
tenant's rows — the connection was a superuser, and **RLS does not apply to
superusers, `BYPASSRLS` roles, or the table owner without `FORCE`**. Policies
can be perfect and every boundary open. `sql/grants.sql` now provisions a
least-privilege role, and the test asserts both directions.

Verified: 56 of 58 tables protected; `users` and `sessions` are documented
exceptions keyed to a person rather than a tenant.

## TASK-104 — Authentication and sessions

**Depends on** 102 · **Estimate** 5 days

Argon2id passwords; opaque session tokens stored as SHA-256 hashes; refresh
rotation with reuse detection via `replaced_by_session_id`; TOTP MFA; invitation
acceptance; password reset; failed-login throttling per account and per IP.

Move the workspace-slug lookup in `apps/api/src/lib/workspace.ts` from an
in-process `Map` to Redis with an invalidation hook — the current cache is
correct for one process and wrong for three.

**Acceptance**

- Registration, login, refresh, logout and MFA enrolment all work end to end.
- Reusing a rotated refresh token revokes the whole session family, and a test
  proves it.
- No password, token or secret appears in any log at any level.
- Throttling is enforced and tested for both account and IP dimensions.
- Session tokens are never stored in reversible form.

## TASK-105 — RBAC and permission enforcement

**Depends on** 104 · **Estimate** 3 days

Five roles mapped to `<module>.<action>` permission sets. A Fastify
`preHandler` that resolves the caller's workspace, role and permissions, and
sets the RLS context for the request. `extra_permissions` grants beyond the
role, additive only.

**Acceptance**

- Every route declares its required permission; a route without one fails a
  startup assertion rather than defaulting to open.
- Every request-scoped query runs inside `withWorkspace()`. A lint rule or test
  catches a handler that does not.
- Cross-workspace access returns 404, not 403 — a 403 confirms the resource
  exists.
- `extra_permissions` cannot widen past the role's ceiling, and a test proves it.

## TASK-106 — Workspace provisioning and settings

**Depends on** 105 · **Estimate** 3 days

Create a workspace from a config file: resolve modules, write
`enabled_modules`, seed the default pipeline and stages, create the primary
location from the config's NAP. Settings API for brand, locale, NAP,
integrations. A config-reload path that re-resolves modules.

**Acceptance**

- `configs/nuesheba/business.json` provisions a complete, usable workspace.
- Changing `modules` and reloading changes the API's mounted routes and the
  dashboard's navigation without a deploy.
- Disabling a depended-on module fails with the dependency named.
- Integration credentials are encrypted at rest and never returned by any read
  endpoint.

## TASK-108 — Observability

**Depends on** 104 · **Estimate** 2 days

Structured JSON logs with request ids propagated from the edge. Error tracking
with source maps. Metrics for request duration, database pool saturation,
queue depth and outbox lag. Alerts on the ones that predict user-visible
failure.

**Acceptance**

- A request id ties a Worker log, an API log and an error report together.
- Credential redaction is verified by a test, not assumed from config.
- Outbox lag and queue depth are alertable — a stalled dispatcher is the
  failure most likely to be silent.
- `/health` and `/ready` behave differently under database loss, and a test
  covers it.
